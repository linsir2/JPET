# 需求文档 PRD

## 登录模块

### 登录角色划分

- 商家
    - 但是注意，商家用户与普通用户均存放在同一个数据库表（`user_tb`）中，只不过`role`字段不同，一个表示“**普通用户**”，另一个表示“**商家用户**”）
- 管理员
    - 管理员存放在单独的表（`administrator_tb`）中

### 登录方式

- **商家登录方式**
    - 用户名 / 邮箱
    - 密码
- **管理员登录方式**
    - 管理员账号
    - 管理员密码

<aside>
⚠️

商家 & 管理员两个角色的登录界面要做一定的划分

</aside>

### 登录后

- 返回基于 **JWT鉴权技术** 的 `refresh_token` & `access_token`（其中payload需要包含 `用户的id` 以及 `用户角色（“普通用户”“商家用户”“主管理员”“子管理员”）`）

<aside>
⚠️

普通用户账号也可以登录该后台系统，只不过由于该用户账号的 `role` 字段的值是 “普通用户”，因此进入后会进入商家注册界面，指引用户进行商家注册。

只有**商家注册完成**并**由管理员审核后**方可进入真正的商家管理界面。

</aside>

---

## 注册模块

<aside>
⚠️

只允许商家进行注册，管理员账户不允许注册！

</aside>

### 商家注册方式

- 用户名（不允许重复）
- 邮箱（不允许重复）
- 密码（至少8位密码，只允许包含数字、大小写英文字母和下划线，且必须含有数字和大小写英文字母）

<aside>
✏️

本质上注册到 `user_tb` ，且初始的 `role` 为 “普通用户”，注册完成后登录后依旧要引导进行商家注册。

</aside>

### 注册后

‼️ 不支持自动登录！注册后需要用户手动进行登录！登录后进入商家注册界面！

## 商家模块

### 商家注册与信息模块

- **商家注册**
    - 注册需求
        - 商家图片（一张）
        - 商家名称
        - 商家简介（只允许纯文字；允许有空格 / 换行效果；不超过500字）
        - 商家标签（允许商家自定义标签）
    - 注册后需要等待管理员审核
    - 管理员审核通过后需将该用户的 `role` 属性修改为 “商家用户”
- **商家用户成功登录后 / 普通用户成功注册商家后进入商家管理界面，该管理界面中包含商家信息板块**
    - 展示内容
        - 商家图片
        - 商家名称（⚠️ 这个和用户名是两个概念，不要混淆）
        - 注册年月日 + 注册时长
        - 商家营业额（根据订单模块中的已完成订单收入进行统计）
        - 商家简介
        - 商家认证（比如：`xxxx官方店`）
        - 商家标签（比如：`狗粮`；`猫粮`；`逗猫棒`）
    - 在该商家信息展示界面支持修改内容
        - 商家图片
        - 商家名称（一个月只能修改一次）
        - 商家简介（只允许纯文字；允许有空格 / 换行效果；不超过500字）
        - 商家标签（允许商家自定义标签）

### 商品模块

- 基于SPU（标准化产品单元） + SKU（库存量单位）模型进行搭建
- **关于商品SPU（标准化产品单元）**
    - 商品名称
    - 商品简介
    - 商品SPU图片URL
    - 商品状态：草稿、待审核、已上架、已下架
        - 状态轮转：`草稿 → 待审核`；`已上架 → 已下架`；`已下架/已拒绝 → 草稿 / 待审核` （⚠️ 其中 `待审核 → 已上架/已拒绝` 的状态轮转由**管理员**执行！！）
    - 商品标签
    - 商品最低价格（单位 RMB）（由所有 SKU 码的最低价决定）
    - 该类商品的核心属性（如狗粮拥有**`优质等级`**、**`重量`**这两种属性（在SPU中暂时不区分这两种属性的值））
- **关于商品SKU（库存量单位，也叫“商品的最小可销售单元”）**
    - 如 `优质等级=2/重量=2000g` 即为一个SKU码
    - 状态：`可售卖`（库存量为0时也为可售卖状态，只是暂时缺货）；`不可售卖`（商家设定为不可售卖）
    - 商品SKU图片URL（可选）
    - 单价
    - 库存量

### 商品管理模块

- **自家商品展示与查询**
    - 所有商品展示与查询（支持过滤）
        - 可根据**商品状态**（`草稿`、`待审核`、`已上架`、`已下架`）、**商品标签**进行过滤展示
        - 可通过**搜索**（匹配商品名称、标签）进行过滤展示
        - 需要实现**分页查询**，默认一个页展示10个左右
    - 商品列表的**粗略展示**内容
        - 图片
        - 名称
        - 最低价格
    - 商品的**详细信息展示（点击类似 `...` 按钮后）**
        - 图片
        - 名称
        - 简介
        - 状态
        - 标签
        - 最低价格
        - 属性
        - 每一条SKU
            - 包含状态、价格、库存量
- **修改单个商品信息**
    - 允许修改图片（支持用户在自己电脑上上传图片）
    - 允许修改商品名称、简介（不超过500字）
    - 允许修改状态（但是要遵循状态修改轮转链，注意 `待审核 → 已上架`不能够由商家自行操作）
    - 允许修改标签
    - 允许修改属性
    - 允许修改 / 新增 / 删除 SKU
- **新增商品（⚠️ 注意下面的必需和可选是针对用户而言，而不是开发而言）**
    - 定义商品图片（必需）
    - 定义商品名称（必需）
    - 定义商品简介（可选）
    - 定义商品标签（可选）
    - 定义商品状态（必需，且只能够选择`草稿` or `待审核`）
    - 定义商品属性（可选，若没有属性就不用填）
    - 定义商品SKU（必需，若没有属性，那么只有唯一一个SKU）
- **删除商品**
    - 这里的删除商品是直接删除该商品以及关联的信息

### 订单模块

- **单个订单信息**
    - 订单号
    - 下单时间（精确到时分秒）
    - 下单用户ID
    - 下单商品名称
    - 下单商品 SPU ID
    - 下单商品 SKU 码
    - 下单数目（注意这里的数目指的是该SKU对应的数目）
    - 下单总价
    - 下单状态（`待发货`，`已发货`，`已完成`，`已取消`）
        - 状态轮转链：`待发货 → 已发货 / 已取消`；`已发货 → 已完成`
- **订单管理**
    - 订单查询
        - 能够根据订单状态过滤查询；能够搜索订单号、用户ID精准查询订单；能够根据商品SPU ID 查询订单
        - 需要实现分页查询
    - 订单修改
        - 能够修改订单状态（只能够修改 `待发货 → 已发货 / 已取消`）（`已发货` → `已完成` 在后续开发中由其它模块完成）
    - 订单删除
        - 不支持删除记录，仅支持 `待发货 → 已取消` 这样的状态转换“软删除”

## 管理员模块

### 用户管理模块

- 关于用户
    - 用户ID（UNIQUE）
    - 用户名（不允许重复）
    - 用户类型（普通用户 or 商家用户）
    - 邮箱（不允许重复）
    - 密码（至少8位密码，只允许包含数字、大小写英文字母和下划线，且必须含有数字和大小写英文字母）
    - 注册时间
    - 个人简介
    - 用户状态：`正常`、`拉黑`
- 用户列表展示
    - 默认根据注册时间倒序排序
    - 能够搜索**用户ID** / **用户名** / **邮箱**精准定位用户
    - 能够通过 **用户状态** / **用户类型** 进行过滤
    - 需要实现分页查询
- 用户信息查询与修改
    - 点击某一个用户后，展示“用户ID”，“用户名”，“邮箱”，“用户类型”，“注册时间”，“个人简介”，“用户状态”。
    - 能够修改用户的状态——从黑名单中恢复，或拉黑。

### 商品上架审核模块

管理员能够审核商家发起的商品上架审核，能够通过 / 拒绝，若拒绝则需要给予拒绝理由

### 商家注册审核模块

用户注册商家后发起审核，管理员能够给予审核——通过 / 拒绝，若拒绝则需要给予拒绝理由。
